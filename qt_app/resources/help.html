MedPharm ERP — Desktop Client User Guide

Medical & Pharmaceutical Enterprise Resource Planning System · PyQt6 Desktop Client
Copyright © 2026 Enlightec Ltd. · www.enlightec.com · Licensed under GPL-3.0-or-later

1. Overview

The MedPharm ERP Desktop Client is the clinical-staff front end of the MedPharm platform. It is built on PyQt6 and runs natively on Linux, macOS, and Windows. The client connects directly to the MedPharm SQLAlchemy database — either to a local SQLite file (the default for single-machine installs) or to the same database used by the Cloud REST API and the Patient Web Portal — so every Desktop action is visible to mobile clients (Android / iOS), the macOS and Windows native clients, and the Flask-based Patient Portal in real time.

The Desktop Client is the primary tool for:

  • Front-desk and clinical staff workflow: appointments, intake, documentation.
  • Prescriber tasks: prescribing, drug-interaction checking, controlled-substance accounting.
  • Pharmacy tasks: medication catalogue browsing, retail/wholesale pricing, classification, DEA scheduling.
  • Back-office billing: invoices, patient payments, insurance claims.
  • Analytics: revenue trends, demographics, top-prescribed medications, provider activity.
Tip. Every screen refreshes automatically on navigation. Use Tools → Refresh Data to force a re-read when another user has just changed something on the same database.

2. Launching the Client

The desktop client is launched in three supported ways:

PlatformCommand
Linux (script)./start_desktop.sh from the project root
Direct Pythonpython3 run_qt.py with the project virtualenv activated
Installed serviceLaunch from the desktop shortcut created by ./install.sh

On first launch the client creates the local database (default medpharm_erp.db), seeds the catalogue with 75+ default medications, and presents the login dialog.

Connecting to a Remote Database

Set the MEDPHARM_DB_PATH environment variable to point at a different SQLite file, or set MEDPHARM_DATABASE_URL to a full SQLAlchemy URL (PostgreSQL, MySQL) before launching. Multi-user installations typically point all clients at the same database file or the same Postgres instance.

3. Signing In

The Login dialog appears every time the client starts. It has three fields:

  • Username — your assigned account name.
  • Password — passwords are hashed with Werkzeug PBKDF2 and never stored or transmitted in plain text.
  • Role — drop-down: Doctor, Nurse, Pharmacist, Receptionist, Administrator, Pharmacy Tech. The client uses this to constrain the menus and module actions you can reach (see Roles & Permissions).
First-time login. The default seeded administrator account is admin / admin123. Change the password immediately on a fresh deployment.

Clicking Sign In validates against the users table. On success the main window opens; on failure an inline error is shown and the password field is cleared.

4. Window Layout

The main window has four regions:

  1. Menu bar (top): File, Tools, Help.
  2. Side navigation (left): one button per module — Dashboard, Patients, Prescriptions, Medications, Appointments, Records, Billing, Messages, Symptoms, Analytics. The Enlightec logo and your role appear above the buttons; your sign-in name appears below.
  3. Workspace (center): the currently selected module. Modules are stacked widgets — switching is instantaneous and the previously visible module retains its filter state for this session.
  4. Status bar (bottom): your sign-in display title, live clock (updates every second), and database connection indicator.

Window minimum size is 1400 × 900 pixels — the layout is designed for typical clinical workstations and is not a touch UI.

5. Dashboard

The first screen shown after login. It is composed of KPI cards, Today's Appointments, and Recent Activity. The dashboard auto-refreshes once a minute and on every navigation back to it.

5.1 KPI Cards

Total Patients
Headcount of patient records in the database.
Active Rx

Today's Appts
Appointments scheduled for the current calendar date.
Monthly Revenue
Sum of paid invoices for the current month.
Pending Bills
Outstanding balance across all unpaid / partial / overdue invoices.
Controlled Rx
Active prescriptions for DEA-scheduled medications (II–V).

5.2 Today's Appointments

Filtered to your provider ID — doctors and nurses see only their own appointments, while administrators and receptionists see the full clinic schedule. Columns: Time, Patient, Type, Status, Reason.

5.3 Recent Activity

Read-only feed of the ten most recent system actions (creations, status changes, payments). Useful as a glance-level timeline and a check that the database connection is alive.

6. Patients

Patient demographics, allergies, diagnoses, billing summary and clinical notes — everything attached to a single patient record.

6.1 Searching

The search bar at the top of the patient list accepts a name fragment (case-insensitive, ≥2 characters). The list is paginated server-side on remote-database installations. Click any row to load the detail panel on the right.

6.2 Detail Panel

The detail panel has the following tabs:

  • Demographics — full name, DOB, gender, blood type, BMI, address (street/city/state/ZIP), email, phone, emergency contact.
  • Allergies — list of allergens, severity, reaction. Surfaced as a red banner in the prescribing dialog when an allergen overlaps with a candidate medication.
  • Diagnoses — ICD-10-coded diagnoses with date and notes.
  • Billing — at-a-glance balance, last payment, last invoice date.
  • Notes — chronologically ordered free-text notes. Each note shows author and timestamp; doctors can edit or delete their own notes.

6.3 Adding a Patient

Click + Add Patient. The dialog enforces the following minimum fields: first name, last name, date of birth, gender, contact (email or phone). Insurance information is optional and can be added later from the Demographics tab.

Activity logging. Every patient creation, edit, and deletion writes a row to the activity_log table — visible on the Dashboard Recent Activity feed and exportable from Analytics.

7. Prescriptions

Create, view, fill, cancel, and bill prescriptions. The Prescriptions module shows one row per Rx with status filtering at the top: All, Active, Filled, Cancelled, Expired.

7.1 List View

Columns: RX#, Patient, Prescriber, Status, Date, Total. Double-click a row to open the detail dialog.

7.2 Detail Dialog

Shows the full prescription header (Rx number, patient, prescriber, status, prescribe date, expiry) and the medication line items (medication name, generic name, dosage, frequency, duration, quantity, refills used / refills allowed, instructions, line cost). The dialog footer carries the action buttons:

  • Cancel Prescription — sets status to cancelled. Available only when status is active.
  • Generate Invoice — creates an invoice line per medication plus a fixed Medical Consultation service line (CPT 99213, $150). The invoice immediately appears under Billing with status draft.
  • Close — dismisses the dialog without changes.

7.3 Creating a Prescription

Click + New Prescription. The dialog walks through:

  1. Patient — search by name, choose from the drop-down.
  2. Medications — click + Add Medication to add a row. Each row has medication search, dosage, frequency (default Once daily), duration, quantity, refills allowed, free-text instructions.
  3. Diagnosis — required free-text justification.
  4. Notes — optional clinical notes.

Before saving, the dialog runs a drug-interaction check across every pair of medications in the prescription. Interactions are surfaced with severity bands (severe / moderate / mild) and the prescriber must explicitly accept or amend before the Save button becomes active. With fewer than 2 medications the check is skipped with the message "Add at least 2 medications to check interactions."

Allergy & controlled-substance flags. If the patient has a recorded allergy to any active ingredient in a candidate medication, the row is highlighted red. DEA-scheduled (II–V) medications produce an additional confirmation prompt with the scheduled-substance disclaimer.

8. Medications

The medication catalogue. Bundles 75+ default medications on first run and can be expanded to ~360 000 entries via the FDA NDC + NIH DSLD bulk loaders, plus DailyMed SPL prescribing-information enrichment. See docs/MEDICATIONS_DATABASE.md.

8.1 Browsing & Filtering

The toolbar carries three filters and a search box:

  • Search — substring on brand name or generic name.
  • All Classes — filter by drug class (e.g. Antibiotic, Analgesic, Antihypertensive…).
  • All Schedules — DEA Schedule II / III / IV / V / non-scheduled.

Catalogue columns: Brand Name, Generic Name, Form, Strength, Class, DEA Schedule, Manufacturer, Average Wholesale Price, Retail Price, Last Updated.

8.2 Detail Panel

Selecting a medication row populates the right-hand panel with the full FDA / DailyMed payload: indications, contraindications, warnings, side effects, dosage, NDC code, route of administration, and the data source banner (default seed, FDA NDC, NIH DSLD, DailyMed SPL).

8.3 Actions

  • 🔎 MedlinePlus — opens the MedlinePlus Drug Information page for the selected medication in your default browser.
  • Simulate Price Update — pharmacy-team utility that re-runs retail-price calculation against the current wholesale price using the configured margin policy. Writes a row to the audit table.
  • Export CSV — saves the currently filtered catalogue to a CSV file for spreadsheet review.

9. Appointments

Schedule, status-track, and document appointments. The screen has two synchronised regions: the calendar widget on the left, the appointment list on the right.

9.1 Calendar & List

Click a date on the calendar to filter the right-hand list to that day. Click All Appointments in the toolbar to clear the date filter. Filters available:

  • Status — Scheduled, Confirmed, In Progress, Completed, No Show, Cancelled.
  • Type — Consultation, Follow Up, Procedure, Medication Review, Other.

9.2 Status Transitions

Right-click an appointment to set its status (or use the status buttons in the detail dialog). Status transitions are logged with timestamp and operator name.

9.3 New Appointment

Click + New Appointment. The dialog requires: patient (typeahead search), provider (drop-down with specialisation), appointment type, date/time picker, duration (in minutes), reason. The save action checks for double-booking on the chosen provider's calendar and prompts for override if a conflict is detected.

10. Medical Records

Per-patient clinical record store: lab results, imaging, procedures, referrals, and free-form notes.

10.1 Selecting a Patient

Use the -- Select Patient -- drop-down or the "Search patient…" field. Until a patient is chosen the right-hand pane shows "Select a patient to view records".

10.2 Record Types

TypeUse For
Lab ResultsCBC, BMP, lipid panel, urinalysis, etc. Numeric ranges and units in the body field.
ImagingX-ray, CT, MRI, ultrasound — typically links the radiologist's narrative.
ProceduresIn-clinic procedures performed (sutures, injections, EKG, biopsy).
ReferralsReferring out — name of specialist, reason, date sent.
OtherFree-form structured note for anything outside the categories above.

10.3 Creating a Record

Click + New Record. The dialog asks for record type, title, and the body content. The author is the currently logged-in user; the timestamp is set on save.

11. Billing & Payments

The accounts-receivable screen. Lists invoices, exposes payment recording, and manages insurance claims end-to-end.

11.1 Summary Cards

Monthly Revenue
Sum of payments dated within the current month.
Pending Bills
Outstanding balance across SENT, PARTIAL, and OVERDUE invoices.
Today's Revenue
Payments recorded today.

11.2 Invoice List

Filterable by status: All, Draft, Sent, Partial, Paid, Overdue, Cancelled. Columns: Invoice#, Patient, Date, Due Date, Total, Paid, Balance, Status. Double-click for detail.

11.3 Invoice Detail

Shows header (number, date, due date, status), patient block, line items (description, code, quantity, unit price, line total), and the running totals (subtotal, tax, total, amount paid, balance due). Buttons: Record Payment, Submit Insurance Claim, Print, Close.

11.4 Recording a Payment

Click Record Payment. The dialog accepts amount, payment method (cash, check, credit_card, debit_card, online, insurance), transaction reference (auto-filled with a UUID prefix if blank), and notes. The balance recalculates immediately. When the balance reaches zero the invoice transitions to PAID.

11.5 Insurance Claims

From the invoice detail, click Submit Insurance Claim to create a claim against the patient's primary insurance. From the toolbar Insurance Claims button you reach the claim management screen — list of all submitted claims, with actions to record claim payments (the payer's portion plus the patient's co-pay) and to attach claim notes (diagnosis codes, procedure codes).

12. Secure Messages

Patient ↔ provider messaging. The same threads are visible in the Patient Web Portal and the mobile clients, so a reply sent here is immediately delivered to the patient's portal inbox.

12.1 Threads

Left panel lists threads, filterable by patient name or subject. Each thread row shows patient, subject, last-message timestamp, and an indicator badge if there are unread incoming messages.

12.2 Thread View

Selecting a thread opens the conversation on the right with a reply composer at the bottom. Type a reply and press Send. Use Close Thread to mark a conversation as resolved (it stays archived and searchable, but moves out of the active inbox).

HIPAA note. Messages are stored encrypted at rest when the database is configured with field-level encryption. The full audit trail (read, reply, close) is recorded for compliance.

13. Symptoms & Conditions Reference

A clinician's reference module — read-only library of symptoms and conditions used to populate diagnosis pickers and triage workflows. Two tabs:

13.1 Symptoms Tab

~30 default symptoms with category and body-system filters. Selecting a row shows description, related conditions, and triage flags (Emergency / Urgent / Routine). Search by name or description.

13.2 Conditions Tab

~25 default conditions, each with ICD-10 code, body system, category (Acute / Chronic / Emergency), description, common symptoms, and treatment overview. Search by name, ICD-10 code, or description. The same library backs the diagnosis picker on the Patient and Records modules.

14. Analytics & Reports

Read-only dashboard for management metrics. Refreshed on navigation; charts are drawn directly with QPainter (no external chart library, so the module loads instantly).

14.1 Stat Strip

  • Patient Count
  • Active Prescriptions
  • Monthly Revenue
  • Top Prescribed Medication (by occurrence in active Rx)

14.2 Charts

  • Revenue (last 6 months) — bar chart of paid invoices, month over month.
  • Patient Demographics — pie chart of patient distribution by age band.
  • Top Prescribed Medications — horizontal bar chart of the ten most-prescribed medications in the past 90 days.
  • Provider Activity — bar chart of appointments completed per provider in the current month.

18. Common Workflows

18.1 New Patient → First Visit → Invoice

  1. Patients → + Add Patient — capture demographics + insurance.
  2. Appointments → + New Appointment — schedule the visit.
  3. On the day of the visit, set the appointment status to In Progress from the Dashboard.
  4. Records → + New Record — document encounter (visit note + any orders).
  5. Prescriptions → + New Prescription — prescribe (interaction + allergy check fires automatically).
  6. From the prescription detail, click Generate Invoice.
  7. Mark the appointment Completed.
  8. Billing → record payment or submit insurance claim.

18.2 Refilling a Prescription

  1. Open the prescription's detail dialog from the Prescriptions list.
  2. Increment refills used on the relevant line item.
  3. Click Save; status remains active until refills allowed is exhausted, at which point it transitions to filled.

18.3 Recording an Insurance Claim Payment

  1. Billing → Insurance Claims.
  2. Select the claim row.
  3. Click Record Claim Payment; enter the payer's amount and optionally the patient's co-pay.
  4. The associated invoice's balance is recalculated; if both halves are received the invoice transitions to PAID.

20. Data & Storage

The Desktop Client speaks to the same SQLAlchemy schema as the Cloud REST API and the Patient Web Portal. The default deployment is SQLite (medpharm_erp.db in the project root); the cloud and multi-clinic deployments are typically PostgreSQL.

  • Default seed: 75+ medications, 30+ symptoms, 25+ conditions, sample users, and a demo patient panel.
  • Bulk loaders (database/load_fda_data.py): FDA NDC + NIH DSLD ingest expanding the catalogue to ~360 000 entries.
  • Prescribing-information enrichment (database/load_dailymed_spl.py): adds indications, contraindications, side effects, dosage, warnings.
  • Backups: ./update.sh writes a timestamped database backup before pulling new releases. For unattended deployments use ./update.sh --auto --install-schedule.

21. Troubleshooting

SymptomLikely cause & fix
Login dialog accepts credentials but main window never appears Database schema is out-of-date. Run ./update.sh; it rebases the schema and migrates safely.
"Database: Disconnected" in the status bar Check MEDPHARM_DB_PATH / MEDPHARM_DATABASE_URL. For Postgres, verify the server is reachable from this host.
Generate Invoice raises a SQLAlchemy DetachedInstanceError Fixed in 1.7.6 (May 2026). Update to the latest release; the Prescription is now eager-loaded before the session closes.
Charts in Analytics show empty axes You don't have enough historical data for the chart's window (Revenue needs 6 months, Top Meds needs 90 days). The empty-state is a placeholder, not an error.
Drug interaction check returns "No known interactions found." for a known dangerous pair The interaction table only ships with default seed pairs. Run database/load_dailymed_spl.py for the full prescribing-information enrichment.
Help → User Guide does nothing Verify qt_app/resources/help.html exists. On Linux, the system needs xdg-open; on macOS and Windows the default URL handler is used automatically.

22. Glossary

TermMeaning
AWPAverage Wholesale Price — the manufacturer's list price used as the basis for retail mark-up.
DEA ScheduleU.S. controlled-substance scheduling: II (highest restriction) through V. Non-scheduled medications carry no schedule.
EHR / EMRElectronic Health Record / Electronic Medical Record. The Patients + Records modules collectively form the EHR.
ERPEnterprise Resource Planning — clinical EHR + pharmacy + billing in one system.
HIPAAU.S. Health Insurance Portability and Accountability Act. See the docs/HIPAA_COMPLIANCE.md for the platform's controls.
ICD-10International Classification of Diseases, 10th revision — the diagnosis-coding system used throughout the Records module.
NDCNational Drug Code — 10-/11-digit FDA product identifier. Surfaced on every medication's detail panel.
SPLStructured Product Labeling — HL7 V3 XML format for FDA-mandated medication labels. Source of the indications/contraindications/warnings text.
CPTCurrent Procedural Terminology — AMA's procedure-coding system used on invoice lines (e.g. 99213 office visit).
